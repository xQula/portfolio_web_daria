# Архитектурный аудит структуры репозитория: SOF Portfolio

Этот документ содержит экспертную оценку текущей структуры каталогов, архитектурных решений и подходов к разработке, используемых в репозитории проекта **SOF (Sense of Form)**. Оценка проведена с позиций Senior Web Developer с учетом современных стандартов веб-разработки (SEO, Performance/Web Vitals, DX, Maintainability).

---

## 🔍 Текущая структура (As-Is)

```text
portfolio_web_daria/
├── index.html                 # Точка входа (мета-редирект на src/html/index.html)
├── package.json               # Зависимости и скрипты (используется live-server)
├── README.md                  # Документация проекта
├── projects/                  # База данных проектов в формате JSON
│   ├── index.json             # Главный реестр файлов видео-проектов
│   ├── video/                 # JSON-файлы с деталями видео (velvet_light.json и др.)
│   └── art/                   # JSON-файлы с деталями арт-карточек
│       └── index.json         # Реестр арт-карточек
├── res/                       # Статические ресурсы (шрифты)
└── src/                       # Исходный код
    ├── html/
    │   └── index.html         # Основная HTML-разметка
    ├── css/                   # Vanilla CSS стили
    │   └── main.css           # Точка импорта стилей (через @import)
    └── js/                    # ES6 JavaScript модули
        └── main.js            # Точка входа JS
```

## 📈 Критический анализ и узкие места (Bottlenecks)

### 1. Мета-редирект на уровне корня (`index.html`)
> [!WARNING]
> **Проблема:** Корневой `index.html` содержит лишь `<meta http-equiv="refresh" content="0; url=src/html/index.html">`. Основной контент лежит по пути `/src/html/index.html`.

*   **SEO (Поисковая оптимизация):** Поисковые роботы (Googlebot, Яндекс.Бот) негативно относятся к мгновенным мета-редиректам. Это ухудшает индексацию, а поисковики могут ошибочно проиндексировать пустую страницу-заглушку вместо реального контента.
*   **Производительность (UX/FCP):** Браузер вынужден делать двойную работу: загружать корневой HTML, парсить редирект, затем слать повторный запрос за реальным HTML. Это увеличивает время отрисовки первого контента (First Contentful Paint).
*   **Хостинг:** Большинство современных платформ (Vercel, Netlify, GitHub Pages) ожидают, что основной `index.html` находится строго в корне. Текущая структура заставляет настраивать правила перезаписи (rewrites) или мириться со ссылками вида `domain.com/src/html/index.html`.

### 2. Каскадный водопад запросов CSS (Waterfall @import)
> [!IMPORTANT]
> **Проблема:** Стили разбиты на файлы и подключаются в `main.css` через директиву `@import`.

*   **Как это работает сейчас:** Браузер загружает `index.html`, видит ссылку на `main.css`, скачивает его. Только после парсинга `main.css` он узнает о существовании `variables.css`, `base.css` и т.д. Браузер начинает каскадно скачивать ещё 7 файлов последовательно.
*   **Влияние на Web Vitals:** Это критически увеличивает время блокировки рендеринга (Render-blocking duration) и ухудшает показатели **LCP (Largest Contentful Paint)**. Современный стандарт требует минимизации количества CSS-файлов при загрузке.

### 3. Избыточное количество HTTP-запросов к JSON (Over-fetching / Network Chatty)
> [!NOTE]
> **Проблема:** Для отображения сетки проектов JS-код сначала скачивает `projects/index.json` и `projects/art/index.json`, а затем делает отдельный запрос `fetch` для каждого файла проекта (10+ запросов).

*   При росте портфолио до 30-50 работ браузер пользователя при открытии страницы будет отправлять 30-50 параллельных HTTP-запросов только ради метаданных. Это создает огромную нагрузку на сеть мобильных устройств и приводит к эффекту "мигающего" или медленно заполняющегося контента.

### 4. Отсутствие сборщика (Vite / Webpack / ESBuild)
> [!TIP]
> **Проблема:** Проект запускается через простой `live-server` без этапа минификации, транспиляции и оптимизации ресурсов.

*   Код JS отдается в браузер "как есть" (без сжатия пробелов, минификации имен переменных).
*   Старые браузеры, не поддерживающие ES-модули (`<script type="module">`), не смогут запустить сайт (отсутствует полифиллинг).
*   Отсутствует автоматическая оптимизация изображений и кэширование (хэширование имен файлов стилей и скриптов при деплое для сброса кэша).

### 5. Именование и организация директорий
*   Папка `res/` — устаревшее название для веба (чаще ассоциируется с Android-разработкой). Современный стандарт — `public/` (для неизменяемых статических ресурсов) и `src/assets/` (для ресурсов, обрабатываемых сборщиком).

## 🛠️ Рекомендации по переходу к современной архитектуре (To-Be)

Мы можем реструктурировать проект без потери гибкости ванильного JS/CSS, внедрив современные инструменты и стандарты.

### Шаг 1: Перенос `index.html` в корень и реорганизация папок
Необходимо избавиться от редиректа. Основной `index.html` должен лежать в корне проекта.

```text
portfolio_web_daria/
├── index.html                 # Главный файл (в корне)
├── package.json
├── vite.config.js             # Конфиг современного сборщика
├── public/                    # Статические ресурсы (шрифты, favicon)
│   └── font/
├── projects/                  # Оставляем данные как внешние API
│   ├── database.json          # Объединенная БД проектов (вместо 15 мелких JSON файлов)
│   └── README.md
└── src/
    ├── css/                   # Стили
    │   ├── main.css
    │   └── ...
    ├── js/                    # Логика
    │   ├── main.js
    │   └── ...
    └── assets/                # Изображения, иконки, обрабатываемые сборщиком
```

### Шаг 2: Внедрение Vite в качестве сборщика (DX & Speed)
Vite идеально подходит для этого проекта: он мгновенно запускается в режиме разработки без сборки (использует те же ES-модули) и делает оптимизированный Production-билд.

1.  **Установка зависимостей:**
    ```bash
    npm install --save-dev vite
    ```
2.  **Скрипты в `package.json`:**
    ```json
    "scripts": {
      "dev": "vite",
      "build": "vite build",
      "preview": "vite preview"
    }
    ```
3.  **Преимущества билда:**
    *   Vite автоматически объединит все импортируемые CSS в один оптимизированный и минифицированный файл (решает проблему Waterfall @import).
    *   JS модули будут собраны в один или несколько файлов (с кэш-хэшем в имени `main.[hash].js`), что исключит лишние запросы.
    *   Обеспечит автопрефиксы для CSS (поддержка старых браузеров).

### Шаг 3: Оптимизация получения данных (Data Consolidation)
Вместо разрозненных файлов:
1.  **Вариант А (Простой):** Объединить все данные о проектах в один файл `projects/database.json`. Браузер сделает всего один быстрый `fetch` запрос и сразу получит весь массив данных для рендеринга.
2.  **Вариант Б (Современный):** Импортировать JSON-файлы напрямую в JS с помощью сборщика:
    ```javascript
    import projectsData from '../projects/database.json';
    ```
    В этом случае данные вшиваются в бандл на этапе сборки, и страница рендерится мгновенно без сетевых задержек на `fetch`!

### Шаг 4: Улучшение SEO-показателей
Внутри `index.html` следует внедрить Open Graph мета-теги для красивого отображения ссылок в мессенджерах (Telegram, VK) и микроразметку Schema.org (например, `Schema.org/CreativeWork` или `Schema.org/Person`), что выведет портфолио на профессиональный уровень видимости в поисковиках.

## 📱 Проблемы адаптивности, SEO и доступности (UX/UI & a11y)

В ходе углубленного анализа стилей и логики были выявлены следующие критические недостатки:

### 1. Полное отсутствие адаптивности в CSS (Responsive Design)
> [!WARNING]
> **Проблема:** В файлах стилей `portfolio.css`, `hero.css`, `header.css` и `footer.css` полностью отсутствуют медиа-запросы (`@media`). 

*   **Ломающийся Grid-сетка:** Группы проектов используют двуколоночную сетку `grid-template-columns: repeat(2, 1fr)`. На экранах мобильных телефонов (ширина менее 768px) это приведет к критическому сжатию карточек до полной нечитаемости. Сетка должна перестраиваться в одну колонку (`1fr`) на мобильных устройствах.
*   **Секция Hero:** На мобильных устройствах левая текстовая часть и правая видео-карточка будут сжаты бок о бок в пропорции 50/50, что полностью сломает визуальную иерархию.
*   **Шапка и подвал (Header & Footer):** Логотип, навигационные ссылки, переключатель тем и кнопка "Start a Project" будут накладываться друг на друга, так как им негде будет уместиться на узких экранах.

### 2. Проблемы с доступностью для клавиатуры (Accessibility / a11y)
> [!CAUTION]
> **Проблема:** Интерактивные карточки проектов (`.project-card`) создаются динамически в `grid.js` как простые теги `div` без возможности фокуса.

*   Пользователи, перемещающиеся по сайту с помощью клавиатуры (клавиша `Tab`), **не смогут взаимодействовать со списком работ** и запустить видео, так как на карточки нельзя сфокусироваться.
*   **Решение:** 
    *   При генерации карточек в JS необходимо добавлять атрибут `tabindex="0"`.
    *   Добавить обработчик события нажатия клавиш `Enter` и `Space` для открытия лайтбокса:
        ```javascript
        card.addEventListener("keydown", (e) => {
          if (e.key === "Enter" || e.key === " ") {
            e.preventDefault();
            openLightbox(project);
          }
        });
        ```

### 3. Отсутствие Open Graph и SEO-микроразметки
> [!TIP]
> **Проблема:** На сайте настроены базовые мета-теги, но отсутствуют теги социальных сетей (Open Graph).

*   При отправке ссылки на сайт в Telegram, VK или WhatsApp ссылка будет выглядеть блекло — без красивого превью-изображения, структурированного заголовка и описания бренда SOF.
*   Отсутствует Schema.org микроразметка (JSON-LD) типа `CreativeWork` или `Person`, которая помогает поисковикам распознавать портфолио и красиво отображать его в выдаче Google/Яндекс.

## 📋 Заключение

Текущая архитектура проекта имеет **отличную модульную структуру внутри `src/`** (чистые ES6 модули, аккуратно разделенные стили). Разработчик отлично проработал декомпозицию.

Тем не менее, **отсутствие мобильной адаптивности, ограничение доступности (a11y) и пробелы в SEO-оптимизации** не позволяют запустить проект в продакшн в его текущем виде.

Внедрение **адаптивных медиа-запросов**, добавление поддержки управления с клавиатуры для карточек и настройка **Open Graph** выведут сайт на уровень коммерческого продукта премиум-класса.
